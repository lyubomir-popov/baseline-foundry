# React component spacing bucket matrix

Coverage checklist derived from the spacing reference inventory in
`feat-bf-shared-alignment/config/react-spacing-inventory.ts`. It contains 145
inventory rows: 142 production-source rows and three story-only rows. The
inventory counts render modules, not spacing-owning parts. The reference
page registry now identifies 184 witness IDs (178 catalog IDs and six explicit
extra-owner aliases) across 59 specimens, so the 145 source rows below are a
source-denominator check rather than the final category count. All currently
identified composite owners are decomposed below; completeness remains open to
new states or declarations found by continued source review.

This file retains the source-denominator checklist. The live part-level ledger
is [`evidence/measured-relationships.md`](evidence/measured-relationships.md),
with each source-owned relationship and captured child in
[`evidence/owner-ledger.json`](evidence/owner-ledger.json). It currently
dispositions 66 global + 54 form + 58 app catalog witnesses and inventories 67
additional owner/variant entries, including a separate CSS styles-primitives
map. The flattened `evidence/relationship-ledger.json` now traces 419 catalog +
117 extra declared relationships. Of 536 relationships, 524 have current
capture references and 12 belong to four explicit source-only boundaries. The
strict evidence verifier passes and checks the current page registry
against `evidence/page-witness-reconciliation.json`. These counts prove the
reconciled model, not that no live source owner remains.
Additional state/declaration coverage and equivalence proofs are not yet
closed. The old composition-derived assignments below are
historical hypotheses, **not current category decisions**. Where they disagree,
the actual owner/measurement ledger and `bucket-table.md` take precedence.

For the real deliverable, every rendered
spacing-owning part must end with evidence-derived classifications for each
owned logical edge and internal spacing relationship. Opposing edges may use
different contracts, and one part may also own a marker canvas or gap.
Regular/control-row, compact separation and Surface inset are current vertical
candidates, not an exhaustive list. Tight-host zero-block participation is a
mode/boundary rather than an evidenced token family. A renderer that only
composes children or establishes external layout is an explicit boundary or
`N/A`; it does not inherit a child part's bucket. Component-internal gaps and
margins remain in scope and must name their real owner. Reusable CSS-only grid,
flow and list primitives also belong to the denominator. External application
shells retain explicit semantic-gap dependency rows without becoming inset
categories or requiring full workflow specimens. See
[`foundation-denominator-audit.md`](foundation-denominator-audit.md) for the
inclusion/exclusion rationale.

All 145 source rows are represented below; the table currently has 152 rows
because Accordion.Item, Badge, Button, Combobox.List, ContextualMenu and Popover
have begun decomposition into independently classified parts or
geometry-changing variants. The evidence column now reconciles every displayed
row to exact owner IDs in the current owner/relationship ledgers, or to a
source-proven boundary. It replaces all 98 formerly `Provisional` evidence cells; the
seed hypothesis columns remain historical and do not acquire approval from a
successful capture.

The reconciliation contains **95 measured-owner rows and 57 proven-boundary
rows** (152 displayed rows; 90 measured-owner and 55 boundary source modules
after merging the seven decomposition duplicates). A decomposed source module
is counted as measured if at least one displayed part owns measured spacing;
its wrapper boundary does not become another source module. There are **zero
currently identified source rows awaiting a missing rendered relationship**.
This is a reconciliation of the declared model, not proof that all possible
states or every CSS declaration have been enumerated. In particular, the h1
reference does not independently measure h2-h6, and a shared CSS owner captured
through another renderer is explicitly identified rather than claimed as an
independent specimen.

`Measured` means current Site/Docs/App capture evidence exists for the named
owner IDs, including measured zero/paint boundaries where relevant; it does
not approve a bucket or normalize legacy literals. Each exact ID resolves to
its selector, source expressions and per-tier capture references through
`evidence/owner-ledger.json` and `evidence/relationship-ledger.json`. A
`Proven boundary / N/A` row states why that renderer adds no independent
component-spacing owner, and names any delegated measured owner or source-only
dependency. The named `reactAlignmentExclusions` and `reactAlignmentStoryOnly`
lists live in `config/react-alignment-coverage.ts` in the reference worktree.
Intrinsic group gaps, pseudo-element compensation and child margin resets are
not discarded merely because their React renderer is a composer.

The earlier 18 measured / 101 provisional row counts described only this seed
table; they no longer describe measurement coverage. Source coverage and
successful catalog capture are not completion claims. T001 must reconcile
every source row to its complete part set, including newly found gaps and
geometry-changing variants, before any final bucket count is asserted.

increasing the 145 React render-module count. It adds the Tabs zero wrapper,

real fenced-code preview now render on the existing axis pages and have fresh
captures; their semantic assignments remain part of the open reconciliation.
The latest supplement also records the required-label pseudo gap, Markdown
task-list margins, empty tree indentation, navigation fade compensation and
editor seam. The h1 heading reference now has a current browser capture.
Repeated Timeline and TokenSwatch observations refer to shared source owners and must not be counted
as independent category pressure.
