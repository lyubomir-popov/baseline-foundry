## 2026-09-19 Card-header phase correction

The prior visible Card-header offset was an audit-composition defect, not a new
spacing category or a production Card defect. In normal block flow, the audit
wrapper allowed the typography role's trailing compensation margins to collapse
through `.spacing-audit__header` and `.spacing-audit__lane-heading`, shifting
later specimens relative to the fixed baseline overlay. The reference audit now
uses grid containment on those wrappers while preserving the typography
compensation, and the production Card CSS is unchanged.

The focused `aligns focused section entry and Card text to its reference while
tracking phase debt` test in
`packages/react/ds-global-form/tests/SpacingAudit.spacing.pw.ts` now checks the
Card text and focused-section reference against the fixed BF-origin baseline in
Site, Docs and App at 16px and 18px roots, with a +1px negative control. This
closes the wrapper-collapse diagnosis only. Shared typography residuals and the
registered complete-denominator downstream phase offsets remain explicit test
debt until CP1; they are not evidence for another Card spacing category.

R2 then measured the real catalog Card-header `h4` nodes rather than the older
focused `.p` comparison. That exposed a separate unresolved production phase:
all six Site/Docs/App × 16/18 root combinations are off the BF origin, and App
places joined and standalone header groups on different phases. The browser
test freezes the exact four-header vector for each combination without
loosening the grid tolerance. This is a CP1 phase blocker, not evidence for a
second Container edge—the independently measured end padding still resolves to
zero for joined seams and 16/16/12px for standalone Surface ends at a 16px root.
