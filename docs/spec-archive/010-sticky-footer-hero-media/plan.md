# Implementation Plan: Resilient Sticky Footer and Hero Media

**Branch**: `feat/010-sticky-footer-hero-media` | **Date**: 2026-08-27 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/010-sticky-footer-hero-media/spec.md`

## Summary

Correct the opt-in site-layout flex contract so a site main child cannot shrink beneath its footer, and scope nested shells to the available application-main block size. Extend the existing hero with a structural lead slot that composes `bf-section is-shallow` before final full-width media, leaving the hero root's established exit padding as the boundary after media. Prove both contracts in generated CSS, reviewable demos, and four-tier browser geometry.

## Technical Context

**Language/Version**: TypeScript 5.8 generating CSS; semantic HTML demos; Playwright browser assertions

**Primary Dependencies**: Existing Baseline Foundry build pipeline, Vite demo server, Playwright 1.58

**Storage**: N/A

**Testing**: `scripts/validate-build.ts`, `scripts/verify-component-behavior.ts`, component screenshot capture and baseline verification

**Target Platform**: Modern browsers supporting logical properties, dynamic viewport units, flexbox, grid, and container queries

**Project Type**: Generated CSS design-system library with static demo catalog

**Performance Goals**: CSS-only layout with no runtime work and no extra network requests

**Constraints**: Flat `bf-*`/`is-*` API; no styled data selectors, BEM aliases, `!important`, consumer overrides, or edits to generated `dist/` output

**Scale/Scope**: Two existing pattern families, four built-in tiers, narrow and wide geometry fixtures
